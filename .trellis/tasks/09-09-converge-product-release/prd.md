# 收敛产品覆盖范围并补齐发布质量门禁

## Goal

将当前上海学区房数据工作台收敛为一个可持续交付的九区产品版本：修复生产构建和 lint 阻塞，限制产品数据覆盖范围，并建立能够阻止回归的 CI/CD 质量门禁。数据库中的其他区域数据继续保留，不能因为产品范围调整而删除。

## Background

- 当前项目是 Next.js 16 + React 19 + TypeScript + PostgreSQL 应用。
- 当前已验证 `pnpm test` 的 223 项测试通过，`pnpm exec tsc --noEmit` 通过，但 `pnpm lint` 存在 13 个 error、22 个 warning，`pnpm build` 因 `app/api/v2/source-schools/route.ts` 重新导出 `runtime` 失败。
- 新版产品入口包括学校查询、学校详情、升学路径、地图、信息源和新版 API；legacy、ops、db 是数据治理或兼容入口。
- 产品目标覆盖区域为：黄浦、静安、长宁、虹口、杨浦、徐汇、闵行、浦东、普陀。
- 其他区域暂不覆盖，但保留数据库记录，供后续扩展和内部审计使用。
- 本任务暂不加入认证、session 或角色权限改造。

## Requirements

### R1. 构建与静态质量

- 修复生产构建阻塞，使 `pnpm build` 在当前 Next.js 版本下通过。
- 修复 `pnpm lint` 的 error；warning 是否清零以不改变行为为前提处理。
- 保持现有 TypeScript 类型检查通过。
- 不通过降低 ESLint 规则、跳过页面或隐藏错误来获得通过。

### R2. 九区产品范围

- 新版产品对用户可见的数据仅来自九个允许区域：黄浦、静安、长宁、虹口、杨浦、徐汇、闵行、浦东、普陀。
- 区名兼容 `浦东` / `浦东新区` 以及带或不带“区”的查询输入，但产品响应中的展示名称保持现有规范。
- 范围限制必须覆盖新版产品的统计、学校列表与详情、升学路径、学区关系、地图、政策/信息源及其相关产品 API。
- 未覆盖区域不能通过默认请求、分页、搜索参数或详情 ID 绕过产品范围限制。
- 数据库、catalog、audit、ingest 和内部数据治理入口不删除其他区域数据；legacy、ops、db 继续保留全量数据。
- 产品界面只展示九个区域的筛选项，不再把其他区域作为可选产品区域。

### R3. CI/CD

- 增加仓库可执行的 CI 配置，在拉取请求和主分支变更时至少运行依赖安装、lint、TypeScript 检查、测试和 production build。
- CI 使用锁文件进行可重复安装，并明确 PostgreSQL 或其他运行依赖的准备方式。
- 增加可审查的 CD 流程或部署产物流程，不能在没有部署目标、凭据和回滚条件时伪装成已完成生产部署。
- 将构建失败作为发布阻断条件；部署步骤必须复用已通过 CI 的构建产物或镜像。

### R4. 文档与回归证据

- 更新 README 中明显过期的 MVP 占位数据、覆盖区域和运行/发布说明，使其与实际产品边界一致。
- 增加或更新针对九区过滤和构建路由回归的自动化测试。
- 验证静态检查、测试、构建和运行中的关键 API；报告未验证的真实部署项。

## Acceptance Criteria

- [ ] `pnpm lint` 无 error。
- [ ] `pnpm exec tsc --noEmit` 通过。
- [ ] `pnpm test` 通过，且包含九区范围过滤回归。
- [ ] `pnpm build` 通过，`source-schools` 等 API route 不再触发 Next.js route segment config 构建错误。
- [ ] 新版产品默认统计和各新版产品 API 不返回九区之外的数据；九区筛选项与返回的 district facets 只包含九区。
- [ ] 使用九区之外学校 ID 访问新版学校详情时不展示该学校，返回既有约定的 not-found/404 行为。
- [ ] 数据库中九区之外的记录数量在变更前后保持不被删除，且内部审计查询仍可访问全量数据。
- [ ] CI 配置在干净环境中可执行上述质量门禁；CD 至少形成明确的构建产物/镜像发布流程和部署前置条件。
- [ ] README 不再把当前真实数据描述为“徐汇 5 所占位数据”或全量 PLACEHOLDER。

## Out Of Scope

- 不删除、迁移或重写九区之外的数据库数据。
- 不补齐其他区域的数据质量。
- 不在本任务加入认证、授权、session、角色权限或管理 API 安全边界。
- 不新增业务功能，如收藏、订阅、房源抓取或自动化政策采集。
- 不宣称已经完成某个未提供目标地址、凭据和回滚方案的生产部署。

## Key Decisions

- 新版产品过滤范围仅覆盖 `/`、`/schools`、`/schools/[id]`、`/pathways`、`/map`、`/sources` 及面向产品的 `/api/v2/*`；`/api/v2/ops*` 属于内部运维入口，继续保留全量。
- `/legacy`、`/ops`、`/db` 和旧版 `/api/*` 继续保留全量数据，供兼容和审计使用。
- CI 负责在干净环境中执行质量门禁；CD 交付可复用的 production Docker 镜像或等价发布产物。由于当前没有确认的生产主机、镜像仓库凭据和回滚目标，本任务不把实际线上部署作为验收条件。
